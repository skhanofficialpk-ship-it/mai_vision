# MAI Coaching Academy — Website & Management System

A complete, production-ready Flutter Web application for **MAI Coaching Academy**, located in School Colony Charbagh, Swat, Pakistan. Built with Flutter, Firebase, Riverpod, and GoRouter.

**Tagline:** Build your future with modern AI

---

## ✨ Features

### Public Website
- **Home** — Hero section, features, founder bio, course previews, stats, CTA, FAQ
- **About** — Mission, vision, values, location
- **Courses** — Full listing of both courses with fees and modules
- **Course Detail** — Per-course curriculum breakdown
- **Admissions** — Online application form, writes directly to Firestore
- **Gallery** — Visual showcase of institute life
- **Contact** — Contact form, WhatsApp/Call/Email buttons, map
- **Certificate Verification** — Public lookup by Certificate ID

### Admin Dashboard (protected, Firebase Auth)
- Overview statistics (admissions, approvals, certificates)
- Admissions management — search, filter, approve/reject, CSV export
- Student management — view all approved/enrolled students
- Course management — add/edit/remove courses, including modules and assigned teacher details (name, address, contact, years of experience)
- Certificate issuance — auto-generated Certificate IDs
- FAQ management — add/edit/delete questions
- Website content management — hero, founder, contact details

## 🔥 Firebase Setup

### 1. Create a Firebase Project
Go to [Firebase Console](https://console.firebase.google.com) and create a new project (e.g. `mai-vision-academy`).

### 2. Enable Required Services
- **Authentication** → Enable "Email/Password" sign-in method
- **Firestore Database** → Create in production mode
- **Hosting** → Enable

> This project runs entirely on the **Firebase Spark (free) plan**. It does not use Firebase Storage, Cloud Functions, or any other paid/Blaze-only feature — do not enable Storage, you won't need it.

### 3. Create Your Admin Account
In Firebase Console → Authentication → Users → Add User:
- Email: `skhanofficial.pk@gmail.com`
- Password: *(choose a strong password)*

This is the only account that can access `/admin`.

### 4. Configure FlutterFire
From the project root, run:

```bash
flutterfire configure
```

This will overwrite `lib/config/firebase_options.dart` with your real project credentials. Select the platforms you need (Web is required; Android/iOS optional).

## 🚀 Running the Project

```bash
# 1. Install dependencies
flutter pub get

# 2. Connect Firebase (only needed once, or when adding platforms)
flutterfire configure

# 3. Run locally on Chrome
flutter run -d chrome

# 4. Build for production
flutter build web

# 5. Deploy to Firebase Hosting
firebase deploy
```

> **Note:** The first time you run `firebase deploy`, you need to log in via `firebase login` and initialize the project with `firebase init` if you haven't already linked it (the `.firebaserc` and `firebase.json` are already included in this project).

## 🗄 Firestore Collections

| Collection | Purpose | Access |
|---|---|---|
| `admissions` | Student applications | Public create, admin read/update |
| `certificates` | Issued certificates (Firestore data only — no PDF/file storage) | Public read (verification), admin write |
| `courses` | Course catalog, including embedded teacher details (name, address, contact, experience) | Public read, admin write |
| `faq` | FAQ entries | Public read, admin write |
| `gallery` | Reserved for future use — the Gallery page currently renders local assets only (`assets/images/`), not Firestore-backed | Public read, admin write |
| `students` | Enrolled student records | Admin only |
| `settings` | Site content (hero, founder, contact) | Public read, admin write |

No collection stores file/image URLs from Firebase Storage — all images come from `assets/images/` bundled with the app, and certificates/courses are pure Firestore documents.

Security rules are defined in `firestore.rules` — they deploy automatically with `firebase deploy`.
